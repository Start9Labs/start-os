StartTunnel gains shell completion and isolates login throttling by server address and public or private access.

## Highlights

- Complete `start-tunnel` commands and options with Tab in new Bash shells.
- Generate completion scripts for other shells with `start-tunnel completions <shell>`.
- Login attempts against one server address no longer block signing in through another. Public and private access have separate limits.
- The first blocked login in each throttle window logs the client IP and server address.
- NAT-PMP clients get an immediate "unsupported version" reply instead of no answer, so they fall back to PCP or UPnP right away rather than retrying for about two minutes.
- The config dialog defaults the WireGuard endpoint to the host in your browser's URL. Edit it to an IPv4 address, IPv6 address, or DNS name before generating the file or QR code.
- CLI `device show-config --endpoint` supplies the same per-config override without changing the WAN assignment used for forwarding and SNAT. The documentation explains the local WAN assignment and upstream NAT requirements.

## Important

Choose an endpoint reachable by the device; an HTTPS reverse proxy may not forward WireGuard UDP. The configured WireGuard port is retained. CLI config generation with a non-public WAN override requires `--endpoint`. Configs already installed on devices remain unchanged.
