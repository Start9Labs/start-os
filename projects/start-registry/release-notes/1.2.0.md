**start-registry 1.2.0 adds private packages, visible only to the signers an admin allows, and serves package icons from their own URLs.**

## Highlights

- **`package access set-private <ID> true` makes a package private.** It disappears from `package get`, `package index`, `index`, and `package signer list` for everyone except admins, its authorized signers, and its readers, which `package access add-reader <ID> <SIGNER>` adds. A reader's requests must be signed: start-cli signs with its developer key, and StartOS signs to the registries added with `start-cli server registry-signing add <URL>`.
- **Package icons are served at `/icons/<id>/<version>`** for StartOS 0.4.0.3 and later, which no longer receive them inline in `package get`. A reverse proxy in front of the registry must forward `/icons/`. A private package's icons are served only to signed requests from signers who can see it. Icons now live in the data directory under `icons/` instead of the index, so index downloads and subscriptions no longer carry them. Existing icons move there on the first start; back up the whole data directory, not just `registry.db`.
