**0.4.1 lets your server finish a backup before restarting or shutting down, updates the NVIDIA driver, and keeps service-to-service IPv6 access available.**

## Highlights

- **Restart or shut down after a backup finishes.** During a backup, the UI asks whether to wait or proceed immediately. A bar shows the pending action and lets you cancel it. Pressing the physical power button also waits for the backup when StartOS can intercept the key. StartOS refuses new backups once a restart or shutdown is committed. See [Creating Backups](https://docs.start9.com/start-os/backup-create.html).
- **CLI restart and shutdown wait for a running backup by default.** Use `start-cli server restart` or `start-cli server shutdown`; add `--force` to interrupt the backup. Cancel a pending action with `start-cli server cancel-deferred-power`.
- **Interrupted operations stop appearing active after the StartOS daemon restarts.** Backup, update, restart, and shutdown indicators reset, along with any pending power action.
- **Legacy service packages convert with built-in SquashFS support**, preserving container filesystem ownership and permissions.
- **The bundled start-cli packs services and adds container images with built-in SquashFS support.** Packaged JavaScript remains readable by the service runtime without changing source permissions, and manifest paths containing apostrophes work during packing and validation.
- **NVIDIA images include driver 580.178.04**, with Linux 7.2 compatibility.
- **Service-to-service IPv6 access stays available** through the internal bridge address while you change access from other networks.
